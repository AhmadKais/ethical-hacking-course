# ✅ מפתח תשובות (Answer Key)

**Q1** ב. **Q2** Confidentiality, Integrity, Availability. **Q3** ג (Black Box). **Q4** אסור לתקוף אותו (מחוץ ל-Scope = לא מורשה); מותר ומומלץ לתעד ולדווח ללקוח ולהמליץ להוסיפו ל-Scope. **Q5** Vulnerability=הפגם, Exploit=ניצול הפגם, Payload=הקוד שרץ אחרי.

**Q6** ב. **Q7** `>` דורס/יוצר קובץ; `>>` מוסיף בסוף מבלי לדרוס. **Q8** ב (750). **Q9** `sudo -l` — מציג אילו פקודות מותר להריץ כ-root; הרשאות sudo שגויות = מסלול הסלמה קלאסי. (גם `find / -perm -4000` תקין.) **Q10** `/etc/passwd` (רשימת משתמשים, קריא לכולם) ו-`/etc/shadow` (Hash של הסיסמאות, root בלבד).

**Q11** ב. **Q12** 22=SSH, 80=HTTP, 443=HTTPS, 445=SMB, 3389=RDP. **Q13** ג (RST). **Q14** פרטית — טווח 10.0.0.0/8. **Q15** 256 כתובות, 254 שמישות.

**Q16** ב (Staged). **Q17** 0 (אפס). **Q18** `banner.split("/")[1]`. **Q19** ג (Tuple).

**Q20** א (אקטיבי — Sublist3r שולח שאילתות; חלק ממקורותיו פסיביים אך הכלי נחשב לאקטיבי/מעורב). **Q21** לזהות תבנית מייל של הארגון (לפישינג/Spraying בתוך Scope); הכלי: hunter.io. **Q22** `site:target.com filetype:pdf`. **Q23** ב (Proxy).

**Q24** ב (`-p-`). **Q25** מזהה גרסאות שירותים; הגרסה מאפשרת חיפוש Exploit ידוע. **Q26** `enum4linux -a <ip>` ו-`smbclient -L //<ip>/` (או nmap smb-scripts). **Q27** ב (gobuster). **Q28** חקר חולשות; הכלי: `searchsploit` (מאגר Exploit-DB המקומי).

**Q29** ב (Reverse Shell). **Q30** כי חומות אש מתירות לרוב תעבורה **יוצאת**; ב-Reverse הקורבן יוצר חיבור יוצא אל התוקף. **Q31** `RHOSTS` (יעד), `LHOST` (התוקף/Kali), `PAYLOAD` (הקוד שירוץ). **Q32** ב (msfvenom). **Q33** להחליף בין Payload Staged ל-Non-Staged; לייצב Shell (upgrade עם python pty / `stty`).

**Q34** דוגמה: `nmap -sn` (חי?) → `nmap -sC -sV -p-` (פורטים/שירותים) → מנייה לפי שירות (nikto/gobuster/enum4linux) → `searchsploit` (Exploit) → Metasploit/ידני (`set RHOSTS/LHOST/PAYLOAD` → exploit) → `whoami`=root. **Q35** whatweb/nikto → gobuster → זיהוי חולשת Apache 2.4.49 (Path Traversal, CVE-2021-41773) → searchsploit → ניצול. **Q36** כי גילוי יסודי של כל שירות/גרסה/הגדרה קובע אילו Exploits רלוונטיים; דילוג על מנייה = פספוס וקטורי תקיפה והכשלת השלבים הבאים.

**Q37** ב (Offline תוקף Hash שנלכד, ללא נגיעה בשירות → מהיר ושקט). **Q38** `rockyou.txt`, ב-`/usr/share/wordlists/`. **Q39** ג (hydra). **Q40** hashcat במצב `-m 5600`; Offline עדיף כי אין Rate-limiting/נעילת חשבון/רעש מול השירות, ואפשר לנסות מיליוני סיסמאות מהר.

**Q41** ב (SQL Injection). **Q42** Insecure Direct Object Reference — גישה למשאב של אחר ע"י שינוי מזהה (`?id=1002`); קטגוריה **A01 (Broken Access Control)**. **Q43** ג (Command Injection / RCE). **Q44** אם ה-payload חוזר רק בתגובה המיידית שלך → Reflected; אם נשמר בשרת ורץ לכל צופה → Stored. **Stored חמור יותר** (פוגע בכל המשתמשים, ללא לינק).

**Q45** ג (EIP). **Q46** Spiking → Fuzzing → מציאת Offset → שליטה ב-EIP → מציאת Bad Characters → מציאת JMP ESP → הזרקת Shellcode. **Q47** ב-Little-Endian, הפוך: `\xaf\x11\x50\x62` — כי x86 מאחסן כתובות בסדר בתים הפוך בזיכרון.

**Q48** ב (`sudo -l`). **Q49** מאגר שמסביר איך לנצל בינאריים לגיטימיים (find, vim, awk...) לבריחה לפקודת מערכת; בשילוב SUID/sudo על אותו בינארי → הסלמה ל-root. **Q50** ב (SeImpersonatePrivilege). **Q51** (1) לייצב את ה-Shell (`python3 pty` + `stty`) כדי לעבוד בנוחות ולמנוע נפילה; (2) Enumeration מקומי (`id`, `sudo -l`, LinPEAS) — כי 90% מההסלמה יושבת במידע שנאסף.

**Q52** ג (`-D`). **Q53** `-sS` (SYN) לא עובר ב-SOCKS proxy → חובה `-sT` (TCP Connect); ICMP ping לא עובר בפרוקסי → `-Pn` כדי ש-nmap לא ידלג על המכונה. **Q54** מקימים מנהרה דרך ה-Pivot: `ssh -D 9050 user@<pivot>` + proxychains, או `autoroute` ב-Metasploit, או Chisel; ואז `proxychains nmap -sT -Pn 10.10.10.30`.

**Q55** ב (LLMNR/NBT-NS). **Q56** בקשת TGS של חשבונות שירות (SPN) ופיצוחם offline; **כל** משתמש דומיין יכול לבקש TGS של כל SPN — זו תכונה של Kerberos, לא באג. **Q57** ב (13100). (NTLMv2=5600, AS-REP=18200, WPA=22000.) **Q58** אוסף את יחסי ה-AD ומצייר גרף; השאילתה המרכזית: **"Shortest Path to Domain Admins"**. **Q59** מתחברים עם ה-hash כמות שהוא (`crackmapexec -H`, `evil-winrm -H`, `psexec -hashes`) כי NTLM מאמת מול ה-hash; הטכניקה: **Pass-the-Hash**.

**Q60** ג (WEP). **Q61** חילופי המפתחות בעת התחברות לקוח ל-AP; Deauth מנתק לקוח קיים שיתחבר מחדש → מזרז את לכידת ה-Handshake. **Q62** Evil Twin לא תוקף את ההצפנה אלא מקים AP מזויף ומרמה את המשתמש **למסור** את הסיסמה (הנדסה חברתית) — לכן חוזק WPA2 לא רלוונטי.

**Q63** ב (Spear Phishing). **Q64** **סמכות + דחיפות**; לדוגמה "מחלקת IT: אפס סיסמה תוך 24 שעות אחרת החשבון ייחסם". **Q65** מדווחים **אחוזים בלבד, ללא שמות**; ממסגרים כהזדמנות להדרכה ולא כענישה — המטרה חינוך ושיפור מודעות.

**Q66** ב (Executive Summary). **Q67** תיאור, השפעה (Impact), **PoC** (צעדים + צילומים), המלצת תיקון, והפניות (CVE/OWASP/CWE). **Q68** (א) **Critical ~9.8** — נגיש מרחוק, ללא אימות, חשיפת נתונים מלאה; (ב) **Low/Info ~3.1** — מידע בלבד ללא ניצול ישיר.

**Q69** דוגמה: `responder` (LLMNR) → NTLMv2 → `hashcat -m 5600` → משתמש דומיין → `GetUserSPNs -request` (Kerberoast) → `hashcat -m 13100` → הרשאות; `bloodhound-python` → נתיב ל-DA → `secretsdump` (PtH) → DCSync → hash של Administrator → Domain Admin. **Q70** מזהים רשת פנימית (`ip a`), מקימים Pivot (`ssh -D` / Chisel), ומשתמשים בסיסמת ה-DB ובמפתח ה-SSH שנאספו כדי להיכנס למכונות פנימיות — משתלבים מודול 11 (Looting), 12 (Pivoting) ו-13 (AD). **Q71** בכולם: לוכדים ייצוג מוצפן של סיסמה (Hash / TGS / Handshake) ומפצחים אותו **offline** במילון (hashcat/john) — אותו עיקרון, מקורות שונים. **Q72** הסיסמה עובדת ב-VPN/OWA → דריסת רגל פנימית → Kerberoasting ו-AD → Domain Admin. שתי הגנות: **MFA** (חוסם גם עם סיסמה נכונה) ו**הדרכות מודעות + סינון מייל** (מונע את הפישינג מלכתחילה).
