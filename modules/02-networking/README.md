# מודול 2 — יסודות רשתות (Networking Fundamentals)

> **מטרות המודול:** להבין כיצד מחשבים מתקשרים ברשת, לשלוט במודל OSI ובמחסנית TCP/IP, להכיר פורטים ופרוטוקולים נפוצים, ולהבין כתובות IP ו-Subnetting ברמה המספיקה לבדיקות חדירה.

> **למה זה חשוב להאקר?** כל תקיפה עוברת דרך הרשת. בלי להבין פורטים, פרוטוקולים וכתובות — אי אפשר להבין מה סורקים, מה מוצאים, וכיצד מנצלים.

---

## 2.1 מודל OSI (The OSI Model)

מודל **OSI** מתאר תקשורת ברשת ב-7 שכבות. כל שכבה אחראית על תפקיד מוגדר ומדברת עם השכבה המקבילה בצד השני.

| # | שכבה (Layer) | תפקיד | דוגמאות | רלוונטיות לתקיפה |
|---|---|---|---|---|
| 7 | Application | ממשק למשתמש והאפליקציה | HTTP, DNS, FTP | חולשות Web, פישינג |
| 6 | Presentation | הצפנה, קידוד, דחיסה | TLS/SSL | פענוח תעבורה |
| 5 | Session | ניהול חיבורים | NetBIOS, RPC | חטיפת Session |
| 4 | Transport | אמינות ותעבורה מקצה לקצה | TCP, UDP | סריקת פורטים |
| 3 | Network | ניתוב וכתובות לוגיות | IP, ICMP | Spoofing, ניתוב |
| 2 | Data Link | כתובות פיזיות (MAC) | Ethernet, ARP | ARP Poisoning |
| 1 | Physical | האותות והכבלים | כבלים, Wi-Fi | האזנה פיזית |

> 💡 **טריק לזכירה (מלמעלה למטה):** *All People Seem To Need Data Processing*.

**מודל TCP/IP** הוא גרסה מקוצרת ומעשית יותר של OSI, בת 4 שכבות (Application, Transport, Internet, Network Access) — והוא זה שרשת האינטרנט משתמשת בו בפועל.

## 2.2 TCP מול UDP

בשכבת התעבורה (Transport) שני פרוטוקולים עיקריים:

| | **TCP** (Transmission Control Protocol) | **UDP** (User Datagram Protocol) |
|---|---|---|
| אמינות | אמין — מוודא הגעה | לא אמין — "יורה ושוכח" |
| חיבור | Connection-oriented | Connectionless |
| מנגנון | לחיצת יד תלת-שלבית (3-Way Handshake) | ללא לחיצת יד |
| מהירות | איטי יותר | מהיר יותר |
| שימוש | דפדוף, מייל, העברת קבצים | DNS, סטרימינג, VoIP |

### לחיצת היד התלת-שלבית (3-Way Handshake)
כך נפתח חיבור TCP — וזהו הבסיס לסריקת פורטים:

1. הלקוח שולח **SYN** (בקשת חיבור).
2. השרת עונה **SYN-ACK** (אישור + בקשה חוזרת).
3. הלקוח שולח **ACK** — החיבור נפתח.

> 🔍 **קשר לתקיפה:** סורק פורטים כמו nmap שולח SYN ומנתח את התשובה — אם חוזר SYN-ACK הפורט פתוח, אם חוזר RST הפורט סגור.

## 2.3 פורטים ופרוטוקולים נפוצים (Common Ports & Protocols)

**פורט (Port)** הוא "דלת" ממוספרת (0–65535) שדרכה שירות מסוים מקבל תקשורת. זיהוי הפורטים הפתוחים = זיהוי השירותים הפועלים = משטח התקיפה (Attack Surface).

| פורט | פרוטוקול | שירות | הערה לתקיפה |
|---|---|---|---|
| 21 | TCP | FTP | העברת קבצים, לרוב לא מוצפן |
| 22 | TCP | SSH | גישה מרוחקת מאובטחת; יעד ל-Brute Force |
| 23 | TCP | Telnet | גישה מרוחקת **לא** מוצפנת — מסוכן |
| 25 | TCP | SMTP | שרת דואר יוצא |
| 53 | TCP/UDP | DNS | תרגום שמות לכתובות IP |
| 80 | TCP | HTTP | אתרי אינטרנט (לא מוצפן) |
| 110 | TCP | POP3 | קבלת דואר |
| 139/445 | TCP | SMB | שיתוף קבצים ב-Windows; יעד תקיפה מרכזי |
| 143 | TCP | IMAP | קבלת דואר |
| 443 | TCP | HTTPS | אתרים מוצפנים (TLS) |
| 3306 | TCP | MySQL | בסיס נתונים |
| 3389 | TCP | RDP | שולחן עבודה מרוחק ב-Windows |

> 💡 שנן לפחות את הפורטים הנפוצים (21, 22, 80, 443, 445, 3389) — הם חוזרים כמעט בכל בדיקה.

## 2.4 כתובות IP (IP Addressing)

**כתובת IP** מזהה מכשיר ברשת. יש שתי גרסאות:

- **IPv4** — ארבעה מספרים (0–255) מופרדים בנקודות, למשל `192.168.1.10`. באורך 32 סיביות.
- **IPv6** — פורמט חדש וארוך יותר (128 סיביות), למשל `2001:0db8:...`, שנועד לפתור את מחסור הכתובות.

### כתובות פרטיות מול ציבוריות
- **פרטיות (Private):** לשימוש פנימי ברשת מקומית, אינן מנותבות באינטרנט:
  - `10.0.0.0 – 10.255.255.255`
  - `172.16.0.0 – 172.31.255.255`
  - `192.168.0.0 – 192.168.255.255`
- **ציבוריות (Public):** ייחודיות וגלויות באינטרנט.

### MAC Address
כתובת פיזית קבועה של כרטיס הרשת (שכבה 2), בפורמט `00:1A:2B:3C:4D:5E`. בניגוד ל-IP שיכולה להשתנות, ה-MAC "צרובה" בחומרה (אך ניתנת לזיוף — MAC Spoofing).

## 2.5 Subnetting (חלוקת רשת) — היסוד

**Subnetting** הוא חלוקת רשת גדולה לתת-רשתות (Subnets) קטנות. עבור בודק חדירות, המטרה המעשית היא **להבין את גבולות הרשת** — אילו כתובות שייכות לאותה רשת מקומית.

### מסכת רשת ו-CIDR
- **מסכת רשת (Subnet Mask)** מפרידה בין חלק הרשת לחלק המארח (Host) בכתובת.
- **סימון CIDR** מקצר זאת: המספר אחרי הלוכסן = מספר סיביות הרשת.

| CIDR | מסכת רשת | מספר כתובות | דוגמה |
|---|---|---|---|
| `/24` | 255.255.255.0 | 256 | `192.168.1.0/24` |
| `/16` | 255.255.0.0 | 65,536 | `172.16.0.0/16` |
| `/8` | 255.0.0.0 | ~16.7M | `10.0.0.0/8` |

> 🔍 **דוגמה מעשית:** כשנסרוק רשת עם nmap נכתוב `nmap 192.168.1.0/24` — כלומר "סרוק את כל 256 הכתובות בתת-הרשת הזו".

---

## 2.6 פרוטוקולי עזר חשובים

- **DNS** (Domain Name System) — מתרגם שם (כמו `example.com`) לכתובת IP. יעד לאיסוף מידע ולתקיפות כמו DNS Spoofing.
- **ARP** (Address Resolution Protocol) — מתרגם כתובת IP לכתובת MAC ברשת המקומית. בסיס לתקיפת **ARP Poisoning** (Man-in-the-Middle).
- **ICMP** — פרוטוקול בקרה; הפקודה `ping` משתמשת בו כדי לבדוק אם מארח חי.
- **DHCP** — מחלק כתובות IP אוטומטית למכשירים ברשת.

---

## סיכום המודול

- **מודל OSI** (7 שכבות) ו-**TCP/IP** (4 שכבות) מתארים כיצד נעה תקשורת ברשת.
- **TCP** אמין ומבוסס-חיבור (3-Way Handshake); **UDP** מהיר וללא חיבור.
- **פורטים** הם דלתות השירותים — זיהוים הוא הצעד הראשון במיפוי משטח התקיפה.
- **כתובות IP** (פרטיות/ציבוריות), **MAC**, ו-**Subnetting/CIDR** מגדירים את גבולות הרשת שנסרוק.
- פרוטוקולי DNS, ARP ו-ICMP הם יעדים ותשתית לתקיפות רבות.

### תרגול מומלץ
1. הרץ `ipconfig` (Windows) או `ip a` (Linux) וזהה את כתובת ה-IP, המסכה וה-MAC של המחשב שלך.
2. הרץ `ping` לאתר וזהה את כתובת ה-IP שהתקבלה מ-DNS.
3. פתח **Wireshark**, לכוד תעבורה, וזהה חבילת SYN של TCP.
