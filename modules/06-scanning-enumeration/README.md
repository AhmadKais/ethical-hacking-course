## 6.1 שלב הסריקה — סקירה

בעוד Recon פסיבי נמנע ממגע, הסריקה היא **אקטיבית** — שולחים חבילות ליעד ומנתחים את התגובות. שני מושגים:
- **Scanning** — מציאת מכונות חיות ופורטים פתוחים.
- **Enumeration (מנייה)** — חפירה עמוקה בכל שירות שנמצא: גרסה, הגדרות, משתמשים, שיתופים, ספריות.

> 💡 **כלל הזהב של המנייה:** *"Enumerate, enumerate, enumerate"*. 90% מהעבודה כאן. כל פורט פתוח = שירות = חולשה פוטנציאלית. אל תמהר לניצול לפני מנייה יסודית.

**מכונת התרגול בקורס:** **Kioptrix Level 1** (מ-[VulnHub](https://www.vulnhub.com)) — מכונה פגיעה בכוונה, מצוינת לתרגול. הורד, טען ב-VirtualBox (או VMware) באותה רשת (Host-Only) כמו Kali.

## 6.2 Nmap — יסודות וגילוי מארחים

**Nmap (Network Mapper)** הוא הכלי המרכזי לסריקה. נתחיל ב**גילוי מארחים** (מי חי ברשת):

```bash
nmap -sn 192.168.56.0/24        # Host Discovery בלבד (ping sweep), ללא סריקת פורטים
```

סריקת פורטים בסיסית על יעד:
```bash
nmap 192.168.56.10              # 1000 הפורטים הנפוצים
nmap -p- 192.168.56.10          # כל 65,535 הפורטים (איטי אך יסודי)
nmap -p 80,443,445 192.168.56.10  # פורטים ספציפיים
nmap -F 192.168.56.10           # מהיר (100 פורטים)
```

### סוגי סריקה עיקריים
| דגל | סוג | הערה |
|-----|-----|------|
| `-sS` | SYN Scan | ברירת מחדל (דורש root), מהיר ו"חצי-פתוח" |
| `-sT` | TCP Connect | לחיצת יד מלאה (ללא root) |
| `-sU` | UDP Scan | לשירותי UDP (DNS, SNMP), איטי |
| `-sn` | ללא סריקת פורטים | גילוי מארחים בלבד |

> 🔍 **קשר למודול 3:** `-sS` שולח SYN ומנתח את התשובה (SYN-ACK=פתוח, RST=סגור) — בדיוק מנגנון לחיצת היד שלמדנו.

### 🎬 הדגמה — נסה בעצמך: סרוק מטרה אמיתית עם Nmap
> נפעיל מטרה עם 4 שירותים, ונמצא אותם עם nmap — בדיוק כמו על מכונת Kioptrix.

**צעד 1 — טרמינל 1: הפעל את המטרה** ([`scan_target.py`](scan_target.py)):
```bash
python3 scan_target.py
```
👀 נפתחים 4 פורטים: 2121, 2222, 8080, 10000. **השאר רץ.**

**צעד 2 — טרמינל 2: גילוי מארחים חיים ברשת:**
```bash
nmap -sn 127.0.0.1            # האם היעד חי?
```
**צעד 3 — סרוק את הפורטים:**
```bash
nmap 127.0.0.1 -p 2121,2222,8080,10000
```
👀 כל ארבעתם `open`. **מצאת את משטח התקיפה.**

🎯 **מה קרה כאן:** nmap ניסה לחיצת-יד לכל פורט; SYN-ACK = פתוח. עכשiו יש לך רשימת שירותים למַנות — הצעד הבא.

**🧠 בדוק את עצמך:** מה עושה `nmap -sn`?
- א) סורק את כל 65,535 הפורטים
- ב) גילוי מארחים חיים בלבד, **בלי** סריקת פורטים
- ג) מזהה מערכת הפעלה

> ✅ **תשובה: ב** — `-sn` (no port scan) רק בודק מי חי ברשת. זהו הצעד הראשון לפני שסורקים פורטים.

## 6.3 Nmap לעומק — שירותים, גרסאות ו-NSE

מציאת פורט פתוח היא רק ההתחלה. עכשיו מְמַנים אותו:

```bash
nmap -sV 192.168.56.10          # Version Detection — גרסאות השירותים
nmap -O 192.168.56.10           # Operating System detection
nmap -sC 192.168.56.10          # סקריפטים ברירת מחדל (NSE)
nmap -A 192.168.56.10           # אגרסיבי: -sV -O -sC + traceroute
```

**הסריקה המומלצת להתחלה** (משלב הכל):
```bash
nmap -sC -sV -oN scan.txt 192.168.56.10
```
- `-sC` סקריפטים · `-sV` גרסאות · `-oN scan.txt` שמירת פלט לקובץ.

### דוגמת פלט וקריאתה
```text
PORT    STATE SERVICE VERSION
22/tcp  open  ssh     OpenSSH 2.9p2 (protocol 1.99)
80/tcp  open  http    Apache httpd 1.3.20 ((Unix) mod_ssl/2.8.4)
139/tcp open  netbios-ssn Samba smbd
443/tcp open  ssl/http Apache/1.3.20
```
כל שורה = יעד פוטנציאלי. שים לב ל**גרסאות הישנות** (Apache 1.3.20, OpenSSH 2.9) — אלה מובילים לחולשות ידועות (סעיף 6.8).

### 🎬 הדגמה — נסה בעצמך: תפוס Banner וגלה גרסה 🚩
> מציאת פורט פתוח זה כלום — הזהב הוא ה**גרסה**. נחלץ אותה בשתי דרכים.

**דרך 1 — nmap עם זיהוי גרסאות** (מול `scan_target.py` שרץ):
```bash
nmap 127.0.0.1 -p 2121,2222,8080,10000 -sV
```
👀 nmap מציג את ה-Banner של כל שירות, כולל `vsftpd 2.3.4` ו-`OpenSSH 2.9`.

**דרך 2 — "תפיסת Banner" ידנית עם netcat** (מתחברים וקוראים מה שהשירות "אומר"):
```bash
nc 127.0.0.1 2121        # FTP →  220 (vsFTPd 2.3.4)
nc 127.0.0.1 2222        # SSH →  SSH-2.0-OpenSSH_2.9p2
nc 127.0.0.1 10000       # ?   →  flag{enumerate_every_open_port}
```
> 💡 אין `nc`? השתמש ב: `python3 -c "import socket;s=socket.socket();s.connect(('127.0.0.1',2121));print(s.recv(100).decode())"`

👀 הפורט 10000 נראה "משעמם" — אבל מי שמנה אותו קיבל דגל. **תמיד מַנֶה כל פורט פתוח.**

🎯 **מה קרה כאן:** שירות רשת לרוב "מציג את עצמו" ב-Banner מיד עם החיבור. הגרסה המדויקת (`vsFTPd 2.3.4`) היא המפתח — בסעיף 6.8 נחפש לה Exploit.

**🧠 בדוק את עצמך:** מהו "Banner Grabbing"?
- א) חסימת פורט
- ב) התחברות לשירות וקריאת המידע (כולל גרסה) שהוא מציג
- ג) הצפנת התעבורה

> ✅ **תשובה: ב** — מתחברים לפורט וקוראים את ה-Banner שהשירות שולח; הוא מסגיר לרוב את סוג השירות וגרסתו המדויקת.

### NSE — Nmap Scripting Engine
```bash
nmap --script vuln 192.168.56.10          # חיפוש חולשות ידועות
nmap --script smb-enum-shares 192.168.56.10
nmap -p 445 --script smb-vuln-ms17-010 192.168.56.10   # בדיקת EternalBlue
```
הסקריפטים ב-`/usr/share/nmap/scripts/`.

### שמירת פלט
```bash
nmap -sC -sV -oA fullscan 192.168.56.10   # -oA = כל הפורמטים (.nmap/.gnmap/.xml)
```

## 6.4 מניית HTTP/HTTPS

אם פורט 80/443 פתוח — יש שרת web. זהו לרוב משטח התקיפה הגדול ביותר.

```bash
whatweb http://192.168.56.10              # זיהוי טכנולוגיות
nikto -h http://192.168.56.10             # סורק חולשות web נפוצות
```

### גילוי ספריות וקבצים נסתרים (Directory Brute-Force)
```bash
gobuster dir -u http://192.168.56.10 -w /usr/share/wordlists/dirb/common.txt
# חלופות:
dirb http://192.168.56.10
feroxbuster -u http://192.168.56.10
```
מחפש נתיבים נסתרים כמו `/admin`, `/backup`, `/config`, `/robots.txt`.

### בדיקה ידנית
- גלוש לאתר, קרא את קוד המקור (`Ctrl+U`), חפש הערות ונתיבים.
- בדוק את `/robots.txt` ו-`/sitemap.xml`.
- זהה את גרסת שרת ה-Web (Header `Server:`) — יעד לחיפוש Exploit.

> 💡 **HTTP מול HTTPS:** בדוק את **שניהם** (80 ו-443) — לעיתים הם מגישים תוכן שונה, ו-HTTPS עשוי לחשוף פרטים בתעודת ה-SSL (שמות דומיין, מיילים).

### 🎬 הדגמה — נסה בעצמך: מנה שרת web וגלה נתיב נסתר 🚩
> נשתמש באתר ACME ממודול 5 כמטרה, ונמצא נתיב ניהול שלא מקושר בשום מקום.

**צעד 1 — טרמינל 1: הפעל את אתר המטרה:**
```bash
python3 ../05-recon/recon_target.py     # http://127.0.0.1:8000
```
**צעד 2 — בדיקה ידנית מהירה — קרא את robots.txt:**
```bash
curl -s 127.0.0.1:8000/robots.txt
```
👀 `Disallow: /admin-panel/` — robots הסגיר נתיב מוסתר.

**צעד 3 — Directory Brute-Force אוטומטי** (מגלה נתיבים גם בלי robots):
```bash
gobuster dir -u http://127.0.0.1:8000 -w /usr/share/wordlists/dirb/common.txt
```
👀 gobuster מוצא נתיבים כמו `/admin-panel` ו-`/backup` (סטטוס 200). אין gobuster? הבדיקה הידנית לעיל מספיקה.

**צעד 4 — בקר בנתיב שגילית:**
```bash
curl -s 127.0.0.1:8000/admin-panel/
```
👀 פאנל ניהול חשוף — דגל בפנים.

🎯 **מה קרה כאן:** Directory Brute-Force מנחש שמות נתיבים נפוצים ומגלה דפים "מוסתרים" שאינם מקושרים. זה משלב את איסוף המידע (מודול 5) עם מנייה אקטיבית.

**🧠 בדוק את עצמך:** מה עושה `gobuster dir`?
- א) מנחש שמות של נתיבים/קבצים באתר לפי רשימת מילים, ומדווח אילו קיימים
- ב) מפיל את השרת
- ג) מפענח סיסמאות

> ✅ **תשובה: א** — הוא שולח בקשות לנתיבים מרשימה (wordlist) ומזהה לפי קוד התגובה אילו קיימים — מגלה דפי ניהול/גיבוי מוסתרים.

## 6.5 מניית SMB

**SMB (Server Message Block)** — פרוטוקול שיתוף קבצים של Windows, על פורטים **139/445**. נפוץ מאוד ברשתות פנימיות, ומקור לחולשות חמורות.

```bash
enum4linux -a 192.168.56.10               # מנייה מקיפה (משתמשים, שיתופים, קבוצות)
smbclient -L //192.168.56.10/             # רשימת שיתופים (Shares)
smbclient //192.168.56.10/share           # התחברות לשיתוף
nmap -p 139,445 --script smb-enum-shares,smb-enum-users 192.168.56.10
```

### חולשות SMB מפורסמות
- **MS17-010 (EternalBlue)** — חולשה קריטית ששימשה במתקפת **WannaCry**. עדיין נמצאת במערכות רבות.
```bash
nmap -p 445 --script smb-vuln-ms17-010 192.168.56.10
```
- **SMB Null Session** — התחברות ללא אימות, חושפת משתמשים ושיתופים.

> 🔍 כשאתה רואה SMB בסריקה — **חשוב "רשת פנימית ארגונית"**. זהו אחד הווקטורים המרכזיים לתנועה רוחבית (מודול 12) ו-Active Directory (מודול 13).

## 6.6 מניית SSH ו-FTP

### SSH (פורט 22)
```bash
nmap -p 22 -sV 192.168.56.10              # גרסת OpenSSH
ssh user@192.168.56.10                     # ניסיון התחברות
```
גרסה ישנה = חולשה אפשרית. SSH הוא גם יעד מרכזי ל-**Brute Force** (מודול 8).

### FTP (פורט 21)
```bash
nmap -p 21 -sV --script ftp-anon 192.168.56.10   # בדיקת התחברות אנונימית
ftp 192.168.56.10                                  # נסה user: anonymous
```
- **Anonymous FTP** — אם מאופשר, מאפשר גישה לקבצים ללא סיסמה — פרס נפוץ.

## 6.7 סריקת חולשות עם Nessus

**Nessus** הוא סורק חולשות אוטומטי (מבית Tenable) — מזהה אלפי חולשות ידועות ומדרג אותן לפי חומרה. הגרסה **Nessus Essentials** חינמית (עד 16 כתובות IP).

### התקנה והרצה
```text
1. הורד את חבילת ה-.deb מ- tenable.com
2. sudo dpkg -i Nessus-*.deb
3. sudo systemctl start nessusd
4. גלוש ל- https://localhost:8834 ← צור חשבון Essentials
5. New Scan → Basic Network Scan → הזן את ה-IP של היעד → Launch
```

### קריאת התוצאות
Nessus מדרג ממצאים: **Critical / High / Medium / Low / Info**, כל אחד עם תיאור, CVE, ותיקון מומלץ.

> ⚠️ **חשוב:** Nessus הוא כלי **רועש** — הוא שולח הרבה תעבורה. הרץ רק על יעדים מורשים, ואל תסתמך עליו לבד — סריקה אוטומטית מפספסת חולשות לוגיות שרק מנייה ידנית תמצא.

## 6.8 חקר חולשות (Searchsploit / Exploit-DB)

מצאת שירות בגרסה מסוימת — עכשיו מחפשים אם יש לו Exploit ידוע.

```bash
searchsploit apache 1.3.20               # חיפוש מקומי במאגר Exploit-DB
searchsploit -m 764                       # העתקת Exploit לתיקייה הנוכחית
searchsploit openssh 2.9
```

- **Exploit-DB** ([exploit-db.com](https://www.exploit-db.com)) — מאגר ה-Exploits הגדול; `searchsploit` הוא העותק המקומי ב-Kali.
- **CVE** (Common Vulnerabilities and Exposures) — מזהה ייחודי לכל חולשה (למשל `CVE-2017-0144` = EternalBlue). חפש ב-[cve.mitre.org](https://cve.mitre.org) או [nvd.nist.gov](https://nvd.nist.gov).

> 🔍 **הזרימה המלאה:** `nmap -sV` מגלה `Apache 1.3.20` → `searchsploit apache 1.3.20` מוצא Exploit → נשמור אותו לשלב הניצול (מודול 7). זהו הגשר בין מנייה לניצול.

### 🎬 הדגמה — נסה בעצמך: מגרסה ל-Exploit
> מצאנו `vsFTPd 2.3.4` בסריקה. עכשיו נבדוק אם יש לו חולשה ידועה — זה הגשר לניצול.

**צעד 1 — חפש את הגרסה במאגר ה-Exploits המקומי:**
```bash
searchsploit vsftpd 2.3.4
```
👀 תוצאה: `vsftpd 2.3.4 - Backdoor Command Execution`. הגרסה הזו מכילה **דלת אחורית מפורסמת** — מי שמתחבר עם שם משתמש שמסתיים ב-`:)` פותח shell בפורט 6200!

**צעד 2 — חפש עוד גרסאות שמצאנו:**
```bash
searchsploit openssh 2.9
searchsploit apache 1.3.20
```
👀 כל גרסה ישנה = רשימת חולשות אפשריות.

**צעד 3 — קרא את פרטי ה-Exploit** (הנתיב מופיע בעמודה הימנית של הפלט מצעד 1):
```bash
searchsploit -p unix/remote/49757.py    # -p מציג נתיב מלא ופרטים (החלף במספר שקיבלת)
# להעתקה לתיקייה הנוכחית לצורך עיון/הרצה:
searchsploit -m unix/remote/49757.py
```
👀 כל Exploit מגיע עם קובץ, תיאור, ולעיתים CVE — זה מה שנעביר לשלב הניצול (מודול 7).

🎯 **מה קרה כאן:** חיברת **גרסה מדויקת** (מ-Banner Grabbing) → **Exploit ידוע** (מ-searchsploit). זו בדיוק שרשרת ההיגיון של בודק חדירות: מַנֶה → חקור → נצל.

**🧠 בדוק את עצמך:** מה מספק `searchsploit apache 1.3.20`?
- א) מפעיל אוטומטית Exploit על היעד
- ב) מחפש במאגר Exploit-DB המקומי חולשות ידועות לגרסה הזו
- ג) מעדכן את Apache

> ✅ **תשובה: ב** — `searchsploit` הוא חיפוש **מקומי** במאגר Exploit-DB. הוא רק מוצא/מציג — ההרצה בפועל היא שלב הניצול (מודול 7).

## 6.9 ארגון הערות

בבדיקה אמיתית תצבור מידע רב. **תיעוד מסודר הוא קריטי** — גם לניצול, גם לדוח הסופי (מודול 16).

- כלים: **CherryTree**, **Obsidian**, **Joplin**, או פשוט תיקיית Markdown.
- מבנה מומלץ לכל יעד: IP → פורטים פתוחים → שירותים וגרסאות → ממצאי מנייה → חולשות אפשריות → פקודות שהרצת.
- **צלם מסך** של כל ממצא חשוב — תזדקק לזה לדוח.

> 💡 **הרגל מקצועי:** פתח קובץ הערות לכל יעד **לפני** שאתה מתחיל, והדבק אליו כל פלט תוך כדי. עדיף מדי-מפורט מאשר לשכוח איך הגעת לממצא.

## סיכום המודול

- **Nmap** הוא הליבה: `-sn` לגילוי מארחים, `-sС -sV -p-` למנייה מלאה, `--script` ל-NSE.
- **מנייה לפי שירות:** HTTP (nikto, gobuster), SMB (enum4linux, smbclient, MS17-010), SSH/FTP (גרסאות, anonymous).
- **Nessus** לסריקת חולשות אוטומטית — כלי עזר, לא תחליף למנייה ידנית.
- **Searchsploit / Exploit-DB / CVE** מגשרים בין גרסה שנמצאה ל-Exploit — הכניסה לשלב הניצול.
- **תעד הכל** — לניצול ולדוח.
